---
title: Repeated keys on MariaDB
description: What each read takes, on MariaDB and MySQL, from a stored object that names one key twice.
mode: reference
---

MySQL keeps only the last member of an object that names one key twice when it stores the document, so every read takes that member. MariaDB stores every member as written. Another writer of the table can store such an object, as in `{"é": "x", "é": "g"}` or `{"\u00e9": "x", "é": "g"}`. The module writes one only from one already stored: an `update()` that writes the object back keeps every member, and one that merges it rewrites it as the `merge()` row says. On MariaDB each read of it answers as follows.

| Read                                                                                                                                                                                               | What it reads                                                                                                                                                                                                                                                                                                                                      |
| -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| The whole document, as `get()` and `run()` return it, and an object returned as it is stored, as by `row.key("o")`, `pluck()`, `without()` or a change feed                                        | The last member, `g`, since the module parses the document's text                                                                                                                                                                                                                                                                                  |
| A path read with a constant key, an index on the path, `getAll()`, `orderBy()`, `group()` or `filter()` through that index, and a join's condition that compares a read with the other row's value | The first member spelled as the path spells it, or else, through the lookup of an escaped key that [MariaDB](./mariadb.md#queries) describes, the first whose decoded key matches. It reads `x` in `{"é": "x", "é": "g"}` and `g` in `{"\u00e9": "x", "é": "g"}`. A key the query computes reads only a member spelled as it spells it             |
| `merge()`                                                                                                                                                                                          | The object it builds holds the member a path read takes, once for each spelling `keys()` lists. An `update()` that writes it stores that, so `get()` then returns `x` for `{"é": "x", "é": "g"}`, and `{"\u00e9": "x", "é": "g"}` is stored with `é` spelled the same way twice                                                                    |
| `filter()` and `not()`, with no index, and a join's condition, that compare a read with a constant string or a value of the same row                                                               | Both the path read in the row above and `JSON_VALUE`, which reads the first member whose decoded key matches. `eq()` holds only where both match, and `ne()` only where both differ, so `{"\u00e9": "x", "é": "g"}` is neither equal to `"x"` or `"g"` nor unequal to `"g"`, and `not()` of `eq()` keeps it for either string                      |
| `eq()` of the object as a whole, `group()` by it, `distinct()` of objects, and a join's condition that compares two objects                                                                        | They compare the stored text, so the object equals no object the query writes, and `group()` and `distinct()` keep two such objects apart wherever their text differs, though each reads back as `{"é": "g"}`. A join's condition between two such objects matches only the same text on MariaDB 11.8, and on 12.3 matches every pair, as on MySQL |
| `keys()`                                                                                                                                                                                           | Each spelling of the key once, so `["é"]` for `{"é": "x", "é": "g"}` and `["é", "é"]` for `{"\u00e9": "x", "é": "g"}`                                                                                                                                                                                                                              |
| `values()`                                                                                                                                                                                         | Every member in order, `["x", "g"]`                                                                                                                                                                                                                                                                                                                |
